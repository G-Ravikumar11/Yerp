# P1 requests to the lead (frozen files)

## 1. Run `store_002_foundation` at start-up (`core/application.py`)

**What:** after `create_all`, call `upgrade_store_002_foundation(engine)` from `app.models.store_core`.

**Why:** on a database created before this branch, `create_all` adds the new tables but not the two new
`store_freeze` columns or the new ledger indexes (including the unique index that stops a movement being reversed
twice). The function is idempotent and additive, and returns what it did.

**Suggested change:** one more step in the start-up list next to "add missing columns":

```python
from app.models.store_core import upgrade_store_002_foundation
...
("store_002_foundation", lambda: upgrade_store_002_foundation(engine)),
```

Fresh databases and the test suite do not need it; `create_all` makes everything there.

## 2. CONTRACT.md: three additions (no change to existing text)

**What:**

- In *Services*, add `freeze_store_for_count(db, store_id, reason, user_id, *, count_doc_id, count_doc_type="COUNT")`.
  While its freeze is open, that count's own `ADJUST_IN` / `ADJUST_OUT` (same `ref_doc_type` and `ref_doc_id`) post and
  reverse; nothing else moves. A plain `freeze_store` still holds everything.
- In *Services*, add the new blocked case to the list: "a movement dated before the last movement of its store and item".
- In *Services*, add the read-only helper `ledger_position(db, store_id, item_id) -> StockBalance`.

**Why:** P4 needs the count freeze, and everyone should know about the back-dating rule before they hit it.

## 3. CONTRACT.md: `store_doc_status_log` is available to every slice

**What:** add the table to the *Tables* section: `doc_type`, `doc_id`, `from_status`, `to_status`, `user_id`, `user_name`,
`note`, `at`.

means one history screen, and P5's reports can read it. Each slice writes rows for its own documents, using
`doc_type` = its `ref_doc_type`.
