# P1 - Masters and Stock enquiry

Backend: `routers/store_masters.py`, `routers/store_enquiry.py`. Frontend: `features/store/masters/`, `features/store/enquiry/`.
Tests: `backend/tests/store/test_masters_enquiry.py`. No new tables: it works on the `store_core` tables.

## Rights
| Right | Allows |
|---|---|
| `store.masters.view` | read stores, bins, staff, freezes, item settings |
| `store.masters.create` | add and edit stores, bins, item settings, unit conversions |
| `store.masters.approve` | assign or remove staff, freeze and unfreeze a store |
| `store.masters.cancel` | switch a store or bin off, remove a unit conversion |
| `store.enquiry.view` | stock on hand, movements, one item's position |

Staff reach only the stores they are assigned to (all with `store.admin`; the account holder reaches every store).
A named `store_id` they cannot reach is 403; lists silently cover only their stores.

## Masters - `/api/store/masters`
- `GET /summary`
- `GET|POST /stores`, `PUT /stores/{id}` (the code never changes; a store holding stock cannot be switched off)
- `GET|POST /stores/{id}/bins`, `PUT /bins/{id}`
- `GET /employees`, `GET|POST /stores/{id}/assignments`, `DELETE /assignments/{id}` (switches it off)
- `GET /stores/{id}/freezes`, `POST /stores/{id}/freeze` (reason required), `POST /stores/{id}/unfreeze`
- `GET /items` (`q`, `configured`), `PUT /items/{id}/settings`, `POST /items/{id}/uoms`, `DELETE /uoms/{id}`

The base unit of an item cannot change once any store holds it. Adding a conversion for an existing unit replaces its factor.

## Enquiry - `/api/store/enquiry`
- `GET /stock` - one row per store and item (`store_id`, `q`, `below_reorder`, `include_zero`, paged), with the total value.
- `GET /ledger` - movements newest first (`store_id`, `item_id`, `movement_type`, `from_date`, `to_date`, `project_id`, paged).
  Reversals are their own rows, flagged by `reversal_of_id`.
- `GET /items/{id}` - one item across the person's stores, last ten movements, and use in the last 30 days.

`GET /api/store/masters` and `GET /api/store/enquiry` still return the skeleton's `{"slice", "items": []}` so the
skeleton smoke test holds; the real data is on the routes above.

## Not applicable
Masters and enquiry hold no documents, so there is no DRAFT-to-POSTED lifecycle and no printable form. The Excel/PDF
exports of stock belong to P5's reports.
