# P1 - Masters and Stock enquiry

Backend: `routers/store_masters.py`, `routers/store_enquiry.py`. Frontend: `features/store/masters/`, `features/store/enquiry/`.
Tests: `backend/tests/store/test_p1_foundation.py`. No new tables: everything is stored in the `store_core` tables
(`store_store`, `store_bin`, `store_user_assignment`, `store_item_settings`, `store_uom_conversion`) and read from the
ledger and balance tables. No frozen file was changed.

## Rights

| Right | What it allows |
|---|---|
| `store.masters.view` | See stores, bins, assignments, item settings |
| `store.masters.create` | Add and change stores, bins, assignments, item settings, unit conversions |
| `store.masters.approve` | Take a store out of use and bring it back |
| `store.enquiry.view` | Everything under Stock enquiry |

Staff only ever see and change the stores they are assigned to (`assert_store_access`); `store.admin` and the account holder
see all of the company's stores. Another company's records answer 404.

## Masters - `/api/store/masters`

* `GET ""` the slice front door (`{"slice": "masters", "items": [stores]}`).
* Stores: `GET/POST /stores`, `GET/PUT /stores/{id}`, `POST /stores/{id}/deactivate|activate`.
  * Code: 2-12 capitals/digits with `-` `_` (it is printed in every document number); unique per company.
  * A code cannot change once the store has ledger entries or document numbers. A store holding stock, or frozen for a count,
    cannot be taken out of use.
* Bins: `GET/POST /stores/{id}/bins`, `PUT/DELETE /bins/{id}`.
* Assignments: `GET/POST /stores/{id}/assignments`, `DELETE /stores/{id}/assignments/{employee_id}` (switches the row off;
  assigning again brings it back). `GET /employees?q=` lists staff to pick from.
* Items: `GET /items?q=&category=&configured=`, `GET /items/{id}`, `PUT /items/{id}/settings`.
  * The base unit cannot change once any stock entry exists for the item (quantities are stored in it).
  * Reorder level / minimum / maximum are not negative, minimum is not above maximum, tolerance is 0-100.
* Conversions: `PUT /items/{id}/conversions/{uom}` (1 `uom` = `to_base_factor` of the base unit, 0.000001 to 1,000,000,000),
  `DELETE /items/{id}/conversions/{uom}`. The base unit itself needs none.
* Every change is written to the audit log.

## Enquiry - `/api/store/enquiry`

* `GET /balances?store_id=&q=&category=&status=&include_zero=` stock by store and item with value and level
  (`NIL`, `BELOW_MIN`, `REORDER`, `OVER_MAX`, `OK`); `/balances/export` is the same as Excel.
* `GET /items/{id}` one item across the stores, with the quantity in its other units.
* `GET /ledger?store_id=&item_id=&from_date=&to_date=&movement_type=&project_id=&ref_doc_type=&ref_doc_id=` movements, oldest
  first. With one store and one item it returns `opening_qty` and `closing_qty`. Reversals are marked (`is_reversal`,
  `reversed`) and never hidden; `/ledger/export` is Excel.
* `GET /documents/{type}/{id}` the movements one document made.

## Screens

`/store/hub/masters` (Stores, with a detail dialog for bins and staff) and `/store/hub/masters/items` (Item settings, with the
units dialog); `/store/hub/enquiry` (stock position) and `/store/hub/enquiry/card?store=&item=` (stock card).

  contract forbids importing from another slice's router.
* The pasted contract v2 mentions Alembic revisions (`store_002_foundation`...). This repo has none and `CONTRACT.md` says tables
  are made by `create_all`, so P1 adds no migration.
